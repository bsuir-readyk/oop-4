Пузик Владислав 451001 -- Отчет по лабораторной работе 4 ООП

**Цель работы**

Расширить существующую иерархию классов приложения без изменения основного исполняемого файла за счет динамически подключаемых модулей, загружаемых из папки во время выполнения.

**Исходные требования задания**

- Расширить иерархию классов через динамическую загрузку модуля.

- Новые модули должны добавлять и расширять базовый функционал.

- Добавить элементы интерфейса для работы с новыми классами.

- Реализовать загрузку модулей из папки.

- Добавление нового модуля не должно требовать изменения существующего кода программы.

**Архитектура плагинов**

В проекте реализована плагинная архитектура на базе Qt и `QPluginLoader`. Основная программа больше не содержит жестко заданный список всех возможных типов транспорта. Встроенные классы и классы из внешних модулей регистрируются в общем реестре `VehicleTypeRegistry`.

Основные файлы архитектуры:

- `src/plugins/plugin_manager.h` и `src/plugins/plugin_manager.cpp` -- загрузчик и менеджер жизненного цикла модулей.

- `src/plugins/vehicle_type_registry.h` и `src/plugins/vehicle_type_registry.cpp` -- реестр доступных типов транспорта.

- `src/plugins/vehicle_plugin_api.h` -- общий API, через который модули взаимодействуют с приложением.

Логика работы загрузчика:

- Приложение сканирует папку `plugins`, расположенную рядом с исполняемым файлом.

- Для каждого файла с расширением `.so`, `.dylib` или `.dll` выполняется загрузка через `QPluginLoader`.

- Загруженный объект проверяется на реализацию интерфейса `VehiclePluginInterface`.

- Модуль регистрирует новые типы транспорта, вкладки интерфейса и расширения отображения флота через `PluginHost`.

- Новые типы сразу становятся доступными в интерфейсе, например в диалоге добавления транспортного средства.

**API для модулей**

Создан файл `src/plugins/vehicle_plugin_api.h`.

В нем описаны основные структуры и интерфейсы:

- `VehiclePluginInterface` -- базовый интерфейс Qt-плагина.

- `PluginHost` -- интерфейс приложения, через который плагин регистрирует свои возможности.

- `VehicleTypeRegistration` -- описание нового типа транспорта, фабрики создания и сериализации.

- `PluginTabRegistration` -- описание новой вкладки интерфейса.

- `FleetUiExtensionRegistration` -- расширение отображения объектов на вкладке «Флот».

Каждый транспорт имеет стабильный идентификатор `type_id`, например `builtin.car`, `plugin.hovercraft`, `plugin.electric_bus`. Этот идентификатор используется при создании объектов, отображении в интерфейсе и сериализации.

**Новые модули**

Добавлены два динамических модуля:

- `src/plugin_examples/hovercraft_plugin.cpp` -- тип `Hovercraft`.

- `src/plugin_examples/electric_bus_plugin.cpp` -- тип `ElectricBus`.

Модуль `hovercraft_plugin` добавляет класс `Hovercraft`, который наследуется от `WaterVehicle`. Класс описывает судно на воздушной подушке, имеет дополнительное поле `cushion_pressure` и переопределяет методы `GetTypeId()`, `GetType()`, `Move()` и `GetInfo()`.

Модуль `electric_bus_plugin` добавляет класс `ElectricBus`, который наследуется от `LandVehicle`. Класс описывает городской электробус, имеет дополнительные поля `battery_capacity` и `route_number`, а также переопределяет методы базовой иерархии.

Каждый модуль:

- содержит новый класс-наследник базовой иерархии `Vehicle`;

- реализует создание объекта через зарегистрированную фабричную функцию;

- регистрирует сериализацию специфичных полей через JSON-объект `payload`;

- добавляет собственную вкладку приложения;

- изменяет отображение своих объектов на вкладке «Флот».

**Сериализация**

Сериализация реализована в файле `src/serialization/vehicle_serializer.cpp`.

Для каждого объекта сохраняются общие поля базового класса `Vehicle`: имя, максимальная скорость, текущая скорость, параметры двигателя и водитель. Специфичные поля конкретного класса сохраняются отдельно в поле `payload`.

При десериализации программа читает `type_id`, ищет соответствующую запись в `VehicleTypeRegistry` и вызывает зарегистрированный десериализатор. Если файл содержит объект плагинового типа, а нужный модуль не загружен, программа выводит ошибку о том, что требуемый тип не зарегистрирован и необходимо загрузить соответствующий плагин.

Для старых встроенных типов сохранена совместимость с именами `Car`, `Truck`, `Boat` и `Submarine`.

**Выгрузка модулей**

Выгрузка модулей реализована безопасно. Каждый объект, созданный плагиновой фабрикой или десериализатором, хранит lifetime-token в базовом классе `Vehicle`. Пока существует хотя бы один объект из плагина, библиотека не выгружается.

Если пользователь пытается выгрузить такой модуль, он переводится в состояние ожидания выгрузки. При этом:

- создание новых объектов этого типа отключается;

- вкладки плагина удаляются из интерфейса;

- расширения вкладки «Флот» отключаются;

- сама библиотека остается в памяти, чтобы виртуальные методы уже созданных объектов оставались доступными.

После уничтожения всех объектов, созданных плагином, повторная выгрузка удаляет регистрации и вызывает `QPluginLoader::unload()`.

**Изменения пользовательского интерфейса**

Интеграция выполнена в файлах `src/ui/main_window.h` и `src/ui/main_window.cpp`.

Добавлена новая вкладка «Модули». На ней отображаются:

- путь к папке `plugins`;

- список загруженных модулей;

- статус каждого модуля;

- ошибки загрузки, если они возникли;

- кнопка обновления модулей;

- кнопка выгрузки выбранного модуля.

Диалог добавления транспортного средства теперь строит список типов не вручную, а из `VehicleTypeRegistry::AvailableTypes()`. Поэтому после загрузки нового модуля новый тип автоматически появляется в интерфейсе.

Также модули могут добавлять собственные вкладки. В данной работе модуль `hovercraft_plugin` добавляет вкладку `Hovercraft`, а модуль `electric_bus_plugin` добавляет вкладку `ElectricBus`.

Кроме того, модули могут изменять отображение объектов на вкладке «Флот». Например, `hovercraft_plugin` добавляет подпись с давлением воздушной подушки, а `electric_bus_plugin` показывает номер маршрута и емкость батареи.

**Перекомпиляция**

Основное приложение не требуется перекомпилировать при добавлении нового типа транспорта. Перекомпилируется только новый модуль, после чего полученная динамическая библиотека копируется в папку `plugins`.

В проекте сборка разделена на:

- `oop_vehicle_core` -- общая библиотека с базовой иерархией, сериализацией, реестром и API плагинов.

- `oop_vehicles` -- основное приложение.

- `hovercraft_plugin` -- динамический модуль судна на воздушной подушке.

- `electric_bus_plugin` -- динамический модуль электробуса.

Команды для компиляции:

```bash
cmake -S . -B build
cmake --build build
```

Или через Makefile:

```bash
make all
```

После сборки модули находятся в папке `build/plugins`:

- `libhovercraft_plugin.so`;

- `libelectric_bus_plugin.so`.

Эти файлы загружаются готовым приложением во время выполнения.

**Вывод**

В лабораторной работе реализована плагинная архитектура на основе Qt `QPluginLoader`.

Система поддерживает динамическое расширение иерархии классов, сериализации и пользовательского интерфейса без изменения и пересборки основного исполняемого файла. Добавление нового транспортного средства сводится к созданию нового плагина и размещению его библиотеки в папке `plugins`.
